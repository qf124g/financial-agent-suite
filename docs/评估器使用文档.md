# 评估器使用文档

本项目评估体系为双层结构：**DeepEval 做离线指标打分，LangSmith 做在线追踪与测试集回归**。

| | DeepEval | LangSmith |
|---|---|---|
| 定位 | 单次回答的质量打分 | 调用链追踪 + 测试集批量回归 |
| 核心指标 | 相关性 / 幻觉 / GEval 自定义 | 路由正确率 / 关键词完整性 |
| 结果查看 | 终端输出 | smith.langchain.com 网页 |
| 对应文件 | `evaluation/deepeval_wealth_advisor.py` | `evaluation/langsmith_evaluation.py` |

---

## 一、DeepEval 评估器

### 1. 三个指标评什么

| 指标 | 评什么 | 对应风险 |
|---|---|---|
| `AnswerRelevancyMetric` | 回答是否紧扣问题（阈值 0.5） | 答非所问、冗余跑题 |
| `FaithfulnessMetric` | 回答是否忠于工具返回的上下文（阈值 0.6） | 幻觉、编造数据 |
| `GEval（风险偏好）` | 回答是否符合客户风险等级（阈值 0.7） | 业务合规 |

### 2. 运行

```bash
export OPENAI_API_KEY="$DASHSCOPE_API_KEY"
python evaluation/deepeval_wealth_advisor.py
```

流程：跑一遍混合式投顾 Agent（customer1 + 上证指数行情查询）→ 三个指标打分 → 终端输出分数与 PASS/FAIL。

### 3. 关键配置：评判模型必须指定 base_url

DeepEval 默认评判器连 OpenAI 官方地址，本项目模型走 token-plan 兼容端点，必须显式指定，否则报 Connection error：

```python
from deepeval.models import OpenAIModel

judge_model = OpenAIModel(
    model="qwen3.7-plus",
    api_key=OPENAI_API_KEY,
    base_url=OPENAI_BASE_URL,   # 缺了这行就连到 OpenAI 官方去了
)
```

### 4. 实测结果解读（2026-11-06）

```
AnswerRelevancy  0.5  FAIL  ← 回答混入了自我介绍，稀释了相关性
Faithfulness     1.0  PASS  ← 行情数据与工具上下文完全一致，无幻觉
GEval 风险偏好    0.0  FAIL  ← 纯行情播报与"风险偏好匹配"指标本身不匹配
```

三条教训：相关性指标能抓到"冗余自我介绍"这类人工难察觉的问题；幻觉满分反证了工具溯源机制有效；GEval 指标要与查询类型对齐（行情播报不该用风险偏好指标评）。

### 5. 已知坑

- `evaluate(print_results=True)` 在 deepeval 4.x 已失效，直接调用即可，结果会自动打印
- `FaithfulnessMetric` 依赖 `retrieval_context` 字段，构造测试用例时必须传入工具返回的原始上下文，否则无法判断"忠于上下文"

## 二、LangSmith 评估器

### 1. 前置条件

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="你的key"     # smith.langchain.com 免费注册（月 5k 条 trace）
export OPENAI_API_KEY="$DASHSCOPE_API_KEY"
```

`LANGSMITH_TRACING=true` 同时会开启三个 Agent 的全链路 trace 上报（零代码改动）。

### 2. 运行

```bash
python evaluation/langsmith_evaluation.py
```

流程：创建/复用数据集 `wealth-advisor-test-dataset`（4 条用例）→ 串行跑评估（`max_concurrency=1` 防限流）→ 结果上报，终端打印实验名，到 smith.langchain.com 查看。

### 3. 测试数据集结构

每条用例 = 输入 + 期望输出：

```python
{
    "inputs": {"user_query": "今天上证指数的表现如何？", "customer_id": "customer1"},
    "expected_outputs": {"processing_mode": "reactive", "should_contain": ["上证指数"]},
}
```

4 条用例覆盖两类：2 条简单行情/概念类（期望走反应式链）+ 2 条复杂规划类（期望走深思熟虑链）。

### 4. 两个评估器评什么

| 评估器 | 评什么 | 为什么是它 |
|---|---|---|
| `processing_mode_evaluator` | 协调层路由是否正确（reactive/deliberative） | 混合式架构的核心质量指标——路由错了，后面链路再准也白搭 |
| `keyword_completeness_evaluator` | 回答对期望关键词的覆盖率 | 回答完整性的代理指标，如"教育金"问题必须含"教育金""建议" |

评估器是普通函数 `(run, example) -> dict`，返回 `{"key", "score", "comment"}`，score 1.0/0.0 或覆盖率比值。

### 5. 结果查看

到 https://smith.langchain.com → 对应 project → Experiments，按实验名（`wealth-advisor-eval-时间戳`）查找，可看到每条用例的分数、trace 详情，多次实验可横向对比（比如改 prompt 前后对比回归）。

### 6. 扩展方法

- **加测试用例**：在 `REACTIVE_TEST_CASES` / `DELIBERATIVE_TEST_CASES` 里追加 dict，重跑即可（数据集已存在时会复用，需先在网页删掉旧数据集或改名）
- **加评估器**：写一个 `(run, example) -> dict` 函数，加进 `evaluators=[...]` 列表

## 三、两套评估器怎么选

| 场景 | 用哪个 |
|---|---|
| 调 prompt 后想快速看单次回答质量 | DeepEval（终端即出分） |
| 验证幻觉（回答是否忠于检索内容） | DeepEval Faithfulness |
| 验证协调层路由逻辑改没改坏 | LangSmith（测试集回归） |
| 对比两个版本的整体表现 | LangSmith（实验对比） |
| 排查 Agent 某一步为什么跑偏 | LangSmith trace 树 |

## 四、常见问题

| 问题 | 原因 | 解法 |
|---|---|---|
| DeepEval 报 Connection error | 评判模型没配 base_url，连到 OpenAI 官方 | `OpenAIModel(..., base_url=OPENAI_BASE_URL)` |
| LangSmith 提示"未启用" | 缺环境变量 | `LANGSMITH_TRACING=true` + `LANGSMITH_API_KEY` |
| 数据集更新了但没生效 | `create_test_dataset` 遇到已存在数据集会复用 | 网页端删旧数据集，或改 `DATASET_NAME` |
| 评估跑得很慢 | 每条用例都要真实跑一遍 Agent | 正常现象，串行防限流，4 条用例约几分钟 |
